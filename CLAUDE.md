# Apply Desk

Native Mac app (Swift, `macos/`) that bundles a local Flask service (`app.py`, `tailoring.py`, `applying.py`, `templates/`, `static/`). It watches the front Chrome tab, scores listings, tunes the resume in Jake's layout, and fills applications with the ` key. See README.md for features.

## Commands
- Unit tests: `.venv/bin/python -m unittest discover -s tests`
- Build + install to /Applications: `./"Build Apply Desk App.command"` (quits the running app; reopen it with `open "/Applications/Apply Desk.app"`)
- Verify the bundle signature after a build: `codesign --verify --deep --strict "/Applications/Apply Desk.app"`
- JS syntax check: `node -e "new (require('vm').Script)(require('fs').readFileSync('macos/autofill.js','utf8'))"`

## Rules
- The user's data lives only in `~/Library/Application Support/Apply Desk/resume_tailor.sqlite3`. Never put personal details in tracked files or test fixtures.
- Answers come from Profile. A standard question with a blank answer is left for the user, never guessed. Self-identification (race, ethnicity, gender, pronouns, veteran, disability) uses the Profile answer or the form's decline option, and is never learned from forms. Never type passwords, never press Submit. Salary questions get "Negotiable" or the posting's own stated pay (a number only when the posting gives one), flagged, and are never learned. Terms/certification boxes and signature fields are filled only when the user set Profile → Terms and signatures (`agree_terms`), never marketing/job-alert boxes (unless required and about this application) or optional data sharing, each flagged in the review. What the user changes on a form is learned for that exact question and beats every rule; Apply Desk's own answers and the model's are never learned.
- The local model (Profile → "A model on this Mac", `use_model`) is Ollama at `127.0.0.1:11434` only, never a remote API. It is asked only what the rules left open, never the questions in `applying.MODEL_NEVER` (self-identification including LGBTQ and accommodation questions, contact details, pay, GPA, consent), and every answer passes `applying.check_answers()` before the filler uses it and is flagged in the review.
- Resume tuning stays truthful: reword and reorder the user's own lines, never change the Jake's template.

## Lessons
- `applying.STANDARD_QUESTIONS`: the first matching pattern owns a question, so specific patterns go before general ones (`clearance_eligible` before `has_clearance`, `government_employee` before `previously_employed`). Patterns run as JS `RegExp` on normalized text, so keep them JS-compatible; `.` stays in "u.s.", so use `[\w.]` or `.{0,n}` rather than `\w+` around it. New yes/no keys also go in the `yesno` tuple in `templates/profile.html`.
- `macos/autofill.js` pop-up lists: Workday leaves closed lists on the page. Always `closeLists()` first, read options with `freshOptions()` (new lists only, nearest the field, settled), and confirm the pick before `note()`. Use `strict` matching for schools, majors, and states.
- Multi-page runs (`macos/autofill.js`, "Run" section): progress lives in the tab's `sessionStorage` (`applyDeskRun`, keyed by role) so a second press or a full page reload continues the same run; `AppDelegate.waitForFill` re-injects the script after a reload. `continueButton()` must never match submit-like text. Test on the mocks in `tests/forms/` (`steps.html`: start page, validation errors, a terms box, a disability form, and a Review page whose Submit must stay unpressed; `workday.html`: stale lists, nested categories, look-alike options; `greenhouse.html`). Serve the folder with `python3 -m http.server`, save a plan from `/api/fill-plan` next to them, then in the browser eval `autofill.js` and call `applyDeskFill(btoa(plan), btoa(pdf), btoa(name))`.
- Search boxes: use `search()` in `macos/autofill.js` (type, then keydown/keypress/keyup Enter, no blur). `typeInto()` blurs, and Workday clears a search box on focus out.
- Workday redraws a search box after each pick. Never hold an input across picks: re-find it (`fillSkills` uses `findInput()`), count pills from the field container, and never pick an option that's already a pill (picking it again removes it). `tests/forms/steps.html` redraws boxes to catch this.
- Workday draws chosen values as tags (`selectedItem`, `role="option"`, inside a `selectedItemList` listbox) right by the box. `openOptions()` must skip them (`chosenTag`), or a slow search reads the tag as its results (a real run added only "Python IDLE"). Skills match by `skillKey()` ("Python (Programming Language)" is Python, "Python IDLE" never is); a skill the list lacks is skipped, not swapped.
- Workday's "Autofill with Resume" garbles entries ("returnsJSON", wrong dates). `fillBlocks` replaces job/school text and dates that differ from the resume unless this run already wrote that field (`run.wrote`, so the user's edits survive a refill). Test with `tests/forms/steps.html#parsed`.
- One role per posting: compare roles with `applying.same_posting()` / `posting_key()` (Workday key = tenant host + requisition, so locale, `%2C`, and `/apply/...` variants match), never raw URL equality. `find_role()` in `app.py` is the lookup for every insert; `merge_duplicates()` runs at startup and backs up the DB to `resume_tailor.before-merge.sqlite3` before its first merge.
- One application record per role and kind (fill run vs saved PDF, `FILL_RECORD`); a redo updates it and unions the review with `unique_review()`. In `autofill.js` add review lines with `record()`, never `state.items.push`.
- Attributing a fill to a role: `roleForApplication` (Swift) sends hints to `/api/role-for-url`, which accepts one only when `applying.page_belongs()` (same host, job-board listing, or company word in the host). A tab's last role is not proof: the user may have navigated to another company.
- Company names go through `applying.company_name()` (end of `identify_role`, and a startup pass in `init_db`): Workday's JSON-LD company is a legal entity ("00100 ACME, INC.", "0090 CORP-Corporate Office"). It strips the numeric code and comma-led legal suffixes, uses the posting's casing, and falls back to the careers-site slug (`globex_external_site`) only for coded internal labels. Keep it idempotent.
- Live-site checks: a headless-Chrome runner (fake identity, fake PDF, first page only, never Next/Submit) found most of these. Test real ATS pages that way, never with the user's data. `isTrap()` skips honeypots; dropdown inputs (`role="combobox"`, often 1px react-select dummies) are exempt.
- Choice questions: `groupQuestion()` reads a radio/checkbox group's question from the text around the group minus option labels (Lever puts options in their own labels); `labelText()` drops a wrapped dropdown's options and hidden helper text. Button choices (Ashby `aria-pressed`, `role="radio"`) go through `fillButtonChoices()`.
- react-select dropdowns (Greenhouse, Pinpoint): `pickCombo()` opens them with their arrow/"Toggle flyout" button (typing alone doesn't open them), finds options by the instance id in the input's aria links, then searches for long lists.
- Pages fill in up to 3 passes (`fillPage`), so questions revealed by an answer (disability Name/Date) get filled. School/job blocks only claim fields they recognize; anything else in a block is answered normally. Without an "Education" heading, `entryBlocks()` needs short labels ("School", "Degree").
- Answers derived from other answers live in `applying.FOLLOW_UPS` (export control, "If you answered No… countries" → N/A, start within N weeks → No for students). Standard patterns skip questions naming another country (UK/Canada right to work).
- Company names: when Workday's JSON-LD has none, `company_from_intro()` reads "At X," or "X's ... team" from the posting; a careers-site slug the posting never uses is not a name. Account pages (`/userHome`, "Candidate Home") are never saved as roles.
- Several tabs fill at once: `AppDelegate.fills` is keyed by Chrome tab id and every call goes through `Chrome.runJavaScript(_:tabID:)`. Chrome throttles background-tab timers, so every wait in `autofill.js` must use `sleep()` (never a bare `setTimeout`): `Autofill.statusScript` calls `window.__applyDeskPump()` on each poll to wake due waits, and `sleep()` bumps `state.beat` so the 90s no-progress give-up doesn't fire mid-page.
- A resume always goes with a fill: `roleForFill` tries the saved role, then reads the page, then `JobListing.findPostingScript` (Workday's `/wday/cxs/<tenant>/<site>/job/...` JSON, or the URL minus `/apply`), and with no role still attaches the base resume (`ResumePDF.make(jobID: nil)`). `attachResume()` avoids "autofill from resume" importers (Ashby has both) and runs once per page.
- Each page is filled, reviewed, and filled again (`reviewPage()`): values that didn't stick are re-set, required leftovers get a neutral answer or "N/A", and blanks are recorded as review lines with an empty `value` (`fields_filled()` and the role page count only lines with a value). When Continue fails the page is refilled once before waiting for the user.
- `applying.PRESUMED` holds standard screening answers (`assumed` ones are flagged "Standard answer picked for you"); the user's own answers and learned answers always win. Essay drafts come from `story_entries()` (resume bullets in first person) and `drafts()`; keep them plain: no "stands out", "passionate", "leverage", or em dashes, and never facts the resume doesn't state. Unknown essay prompts get the closest resume story, flagged as a starting point.
- Tick boxes are grouped by where they sit (`choiceGroup()`), not by name (Ashby names each box after its label and repeats questions). A field's helper text under its label (`detailOf()`) is tried when the label alone gets no answer. Comboboxes with their own arrow button (Ashby) go through `pickCombo()` too.
- Local model flow: `reviewPage()` → `askModel()` puts open questions in `state.ask`; `AppDelegate.waitForFill` posts them to `/api/suggest` (170s timeout) and hands answers back with `Autofill.answersScript`; an empty list means "carry on". Essay templates wait while `holdDrafts` is true, then fill whatever the model didn't. `clean_essay()` drops sentences with stock phrases, closing sales lines, numbers not in the user's material, and claim words ("led", "improved") the resume doesn't use. Send `"think": false` to Ollama: Gemma 4 otherwise spends its whole token budget thinking and returns empty content. `MODEL_RULES` must say first that essays get written: a general "leave it empty unless stated" rule made Gemma blank every essay. Test changes with real Gemma, not a stub. Keep `availability`, `cover`, `plans`, and "describe your X experience" rule-written.
- GPA: `gpa` stays the typed answer; `gpa_range` (Profile → Education) is only the fallback for lists with no N/A. `best()` reads a decimal-range variant as numbers (`closestBracket()`: most overlap, then narrowest, then lowest), so "3.50 - 3.74" and "3.5 and above" work. `gpaFloor()` answers "GPA of 3.0 or higher?" only when the range settles it. `gpa` sits before `currently_student` in `STANDARD_QUESTIONS` (Lever: "If you are currently enrolled..., what is your GPA?").
- Pronouns are a disclosure (`eeo_pronouns`), listed before gender so "gender pronouns" asks for pronouns. Unlike other self-identification, an answered one may be typed into a text box (`typed`).
- A blank LinkedIn in Profile means the user doesn't share it: `noLinkedIn()` types N/A in a required text box (flagged; a `type="url"` box stays blank and still needs them) and keeps optional boxes out of the review.
- Multi-page mock runs need a plan with a role (`/api/fill-plan?job_id=N`, the term comes from the posting) and a PDF (the resume is required). Without them the run correctly waits, which looks like a regression.
- Stop and restart: pressing ` stops at once. `sleep()` rejects with `STOPPED` and `stopCheck()` runs at each field, so new loops that fill without waiting need a `stopCheck()`. A later press only fills blanks: `run.wrote` (fields it typed), `run.first` (a fingerprint of each entry field when first seen; a changed field is the user's and is never replaced), `run.adds` (sections it added entries to). These also go in `localStorage` (`applyDeskMarks:<role>`, names and hashes only, never answers) so a closed tab continues. Test with `tests/forms/restart.html`, clearing `localStorage` first. The stop flag no longer means "first page only", so live-site runs without Next are for single-page forms.
- Typing: never call `execCommand` directly. It lands in whatever has focus, so a redrawn field's text went into the last box typed (a real run added the school to Last Name). Use `insertText()` / `focusedOn()`, which set the value directly when the field can't take focus. `reviewPage()` also restores a name or email with anything stuck to it.
- Resume once: `attachResume()` skips when any non-cover, non-importer upload box holds a file or shows a filename beside it (`showsFile()`; Workday empties the box and lists the file), and tracks attached pages on `window`. Without this, a restart fed the leftover "Additional documents" box.
- Learning: `remember()` compares with `state.items`: the same value is Apply Desk's own (ignored), a different one is the user's correction (`learnFix()`, `corrected: 'yes'`). The listener records trusted changes in `sessionStorage.applyDeskSeen`, lists only when their shown value changed; `AppDelegate.collectCorrections` sends those to `/api/answers` while the user reviews, since they may submit without pressing ` again. `wanted()` checks exact learned answers before every rule except self-identification, salary, and `never`.
- Verifying answers: dump `applications.review` from the local DB and read every question and value against what the user said; run the questions through the filler on a generated page with the fake identity. That found "require sponsorship for work authorization" owned by `authorized_us` (it now skips a `require...sponsor` opening), "entitled to work without sponsorship" owned by `needs_sponsorship`, and "pronounce your name" read as pronouns (`\bpronouns?\b`).
- `best()`: `saysNo` keeps a negative option ("Did not obtain high school diploma") from matching a positive answer. A `month of YYYY MM` variant goes through `closestDate()` (exact month, a range or term holding it, then the year), since a bare year picked "January 2028". Profile's graduation date beats the resume's; sentences drop the day. `preferred_start` (Profile) answers start-date questions for summer or unnamed internship terms, in the term's year (`program_start()`).
- Tick boxes: `tickTrue()` / `statementHolds()` tick a box only when `wanted()` on its own label says so, with negation handled ("I am not authorized" stays off). `SCHOOL_FIELD` is the school field itself, not "High School Name" or "Technical Accomplishments - School/Internships". In entry blocks, "Employer City" is checked before "employer".
- Essays and blanks: a resume story only goes where it answers the question (`storyPrompt`: experience, project, a time), and "N/A" only where the form leaves room for it (`noAnswerNeeded`: opens with "if", or says to enter N/A). A wrong draft or N/A is worse than a blank: blanks wait for the model or the user. A short question in a textarea goes to the contact rules first ("What is your preferred name?"). With `use_model` on and Ollama closed, `AppDelegate.fetchPlan` starts Ollama in the background and fetches the plan again.
- Link fields: GitHub goes in any website/portfolio/URL field when there's no personal site, with `https://` added. Workday's empty "Websites" section gets one entry (`addWebsite`).
- When a step has required blanks, the run waits (`waitForUser`) instead of stopping, with `__applyDeskBusy` off so the user's answers are learned; single-page forms just list them.
- `role_odds()` in `app.py`: company type comes from the company name or the posting introducing itself, never any mention ("deploys to AWS"). Big tech and quant are capped at "Unlikely" for freshmen. Keep it separate from the fit score.
- Review checks a value beside its own label, not anywhere on the page ("Virginia" also appears inside the school's name).
- PDF text: pypdf layout mode keeps columns but glues words; `respace()` in `app.py` repairs it with words from the bundled PDFKit helper (`macos/tools/pdftext.swift`, passed as `APPLY_DESK_PDFTEXT` by `Backend.swift`). Without the helper (plain Python, tests) text is unrepaired.
- Build signing: sign `Contents/MacOS/pdftext` before the app, without `--deep`, or `codesign --verify` fails with "nested code is modified".
- Keep the designated requirement pinned to `identifier "com.ajeet.applydesk"`; changing it resets the user's Chrome automation permission.
